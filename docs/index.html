What it is

A runtime, not a download

It maps and runs a game executable that you already have on disk. It never downloads, hosts, unlocks or decrypts anything — the files in, come from you. Source only: build it yourself.

RTX first

Waves of 32, view heaps capped at the card's million, wide indirect dispatches, the console's float rules spelled out to what every host agrees on. The Radeon settings stay behind switches; an RTX card needs none of them turned.

Grown in the open

Rust, GPL-3.0-or-later, descendant of VIctory. The commits taken from other forks keep their authors' names. Every switch is documented where it is read.

The RTX port

What an RTX card needs

Wave32 lowering that leaves partial groups alone, barriers that wait for every thread, a view heap clamp and its countermeasures (VICTORY_DYNAMIC_SLOTS), dispatches that run past 65,535 groups. The whole table is in docs/rtx.md.

Taken from the ranked forks

Dynamic slots on the capped heap, the title patches (render scale, own upscaler, watchdog off), the pipeline skip list, VICTORY_BVH_MISS, the constant-slot marks, sixteen-bit halves, the launchers; from the 8 GB fork, the constant view sizes and the clamps' waits. What stayed out, and why: the eval.

Honest numbers

Every frame-time figure of the base README is a Radeon RX 7900 XTX's. The RTX measurements are still open — the port's notes keep an unknowns list instead of made-up ones.

Getting started

  1. Install Rust and clone the repository.
  2. Build the runtime with diagnostics: 
    cargo build --profile diag -p victory --features diagnostics
  3. Start the launcher and point it at the game you own: 
    xenith.cmd
    or the graphical one: 
    xenith-ui.cmd
  4. Or launch a way directly: 
    scripts\play-nvidia.ps1 -Exe "D:\Games\GTA VI\game_scarlett_master.exe"
    with -Resolution, -Adapter, -Quality and -RayTracing on top.

Both launchers keep their choices in xenith.ini next to themselves; it is a special copy of Xenith VI's launcher, changed for this fork. The runtime keeps none of it.

The launchers

Both Xenith copies keep their choices in xenith.ini next to themselves; they are a special copy of Xenith VI's launcher, changed for this fork. The runtime keeps none of it.

xenith.cmd — the menu

A numbered console menu: play in every mode, settings, the shader preload. The NVIDIA card is found on its own, and the settings live beside Xenith's own in xenith.ini (thirteen items, the DLSS folder among them).

xenith-ui.cmd — the window

A dark desktop window: the run's settings on cards, the adapter picked on its own, the cache, saves and DLSS folders on rows of their own, and a Console tab with the run's log, performance monitoring, a command line and log saving.

Performance log for stability checks

Turn it on in Settings

Enable Perf log and choose a sample interval from 1 to 60 seconds. The sampler runs alongside the game and stops when the run exits; it does not change the render settings.

Find the CSV

Each run gets its own timestamped victory-perf-*.csv in the configured log folder. Without a custom folder, Xenith uses debug-runs in the repository.

Compare stability over time

Rows include system CPU and RAM, GPU utilization and memory, plus the tracked run's PID, CPU and working-set memory. Keep the CSV beside the matching run log when reporting a crash or slowdown.

The same sampler is available from the script: scripts\play-nvidia.ps1 -Exe "D:\Games\game.exe" -PerfLog -PerfEvery 2. The console launcher exposes the toggle and interval in Settings as well.

The debug console, in the window launcher

The Console tab of xenith-ui.cmd shows the run's log as it is written, and answers a few typed commands of its own (click Run or press Enter):

CommandDoes
helplists the commands
play / stopstarts the run with the settings on the cards / ends it

open cache (also saves, dlss, game, log)the named place in Explorer
save <path>writes the log to the full path you name — any folder, any name

Saving works three more ways, all to any location:

  1. Save log… — a file dialog opens; the default name carries the time, victory-run-yyyyMMdd-HHmmss.log, and the folder is yours.
  2. auto — a checkbox: give the console a log folder and the log is written into it as victory-run-…log as soon as the run exits, with no click from you.
  3. copy — the log on the clipboard, to paste wherever.

Experimental DLSS Super Resolution

The opt-in DLSS path intercepts the title's FFX upscaling dispatch and submits its color, depth, motion-vector, exposure, jitter and output resources to NVIDIA NGX. Other dispatches and failed NGX attempts fall back to the title's original FFX implementation. This is Super Resolution only; DLSS Frame Generation is not included.

  1. Get the licensed NVIDIA DLSS SDK locally. Build on Windows with its import library: set VICTORY_DLSS_SDK to the SDK root and run cargo build --locked --profile diag -p victory --features diagnostics,dlss. The SDK root must contain lib\Windows_x86_64\x64\nvsdk_ngx_d.lib.
  2. Set Xenith's DLSS folder or -DlssDir to a folder containing nvngx_dlss.dll (the official package's lib\Windows_x86_64\rel folder). The SDK and runtime binaries are not included in this repository; do not rename the AMD FFX DLLs to stand in for NGX.
  3. Select dlss and start with the known-stable 720p render profile. Higher resolutions and live-game output are not yet verified; if the build lacks the feature or NGX cannot initialize/evaluate, logs explain the reason and the original FFX path runs instead.

The shader and pipeline preload

The preload translates shaders and makes host pipelines before a run, reducing first-seen hitches. Enable it in the launcher settings to be asked before each launch:

  1. Enable preload in the launcher settings or use -Preload on the script; the window asks before each launch and shows the current stage with an indeterminate progress bar (the backend has no reliable overall percentage).
  2. It runs victory translate (shader translations into the cache) and then victory warm (host pipelines made) - minutes on the first pass or after a cache refresh.
  3. The result is kept in the cache folder (VICTORY_CACHE_DIR, the script's -CacheDir): the runs after start without the first-seen hitches.

Game textures and world assets are streamed by the title at runtime, not bulk-loaded by this preload. D3D12 residency is budgeted and can fail or stall when the GPU is over budget; see Microsoft's residency guidance.

The switches, for an RTX card

SwitchDoes
VICTORY_DYNAMIC_SLOTSdescriptor slots for tables made afresh; answers the card's capped view heap so tables are not refused and draws dropped
VICTORY_RENDER_SCALErenders at a part of the output's size (0.2–1.0); the title's own upscaler stretches it back
VICTORY_SKIP_PIPELINESnever makes the pipelines of the named 16-digit shader hashes (scripts/rt_off_hashes.txt pre-fills it)
VICTORY_BVH_MISS=1ray walks end at the root and miss: a ray pass cannot hang with the structure builder off
VICTORY_INDIRECT_WIDE=0dispatches cut at 65,535 groups again (unset, the card is taken to run them wide)
VICTORY_GROUP_SYNCbarrier waits: 2 every group (safe), 1 only the ones every lane runs, 0 none
VICTORY_CLAMP_WAITS=0leaves the indirect clamps' two global waits out
VICTORY_PIPELINE_WAIT_ONCE=0a pipeline past its wait budget waits again every frame, as before
VICTORY_MEMORY_CARD_MBthe most of title memory on the card (4,096)
VICTORY_D3D12_ADAPTERwhich card makes the device (name part or index)
VICTORY_UPSCALER=dlssexperimental NGX Super Resolution at the title's FFX upscale dispatch; failed calls fall back to the title's original FFX implementation
VICTORY_DLSS_DIRfolder containing the NGX runtime nvngx_dlss.dll
VICTORY_DLSS_TRACE=1diagnostics build: press F9 in gameplay to log one frame of compute shader and resource metadata
VICTORY_SAVES_DIRwhere the title's saves live, instead of the data folder
shader preloadvictory translate and victory warm before a run (or the launcher's preload tick): no first-seen-places hitches

Troubleshooting

SeenTry
hitches as new places are first seenrun the preload once (menu 7, -Preload, the window's tick); the cache keeps the result for the runs after
a ray pass hangs with ray tracing onVICTORY_BVH_MISS=1: the walks end at the root and miss instead. The skip list leaves the passes out entirely
stretched bodies, rainbow skin, black blobs, overbright roomsthe quality patches (-Quality, the launchers' default). Leaving them off buys frames and costs picture
the wrong card of two picked-Adapter or VICTORY_D3D12_ADAPTER — part of the name or the index. The window's box lists what was found
a Smooth Motion profile that never appliesit must be set for victory_sm.exe, the copy the script starts by default (-NoSmoothMotion skips the copy)
the driver's shader cache behaving badlyrun the launcher from a normal window, not as administrator: the driver keeps its cache elsewhere then
saves in the wrong placeVICTORY_SAVES_DIR or -SavesDir — where the title's saves live instead of the data folder
