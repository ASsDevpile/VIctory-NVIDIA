VIctory NVIDIA

Grand Theft Auto VI (Xbox Series X|S), played from the files you already own, on an NVIDIA RTX card over Direct3D 12 — retargeted from the Radeon work, with the best of the community's RTX forks folded in.

What it is

A runtime, not a download

It maps and runs a game executable that you already have on disk. It never downloads, hosts, unlocks or decrypts anything — the files in, come from you. Source only: build it yourself.

RTX first

Waves of 32, view heaps capped at the card's million, wide indirect dispatches, the console's float rules spelled out to what every host agrees on. The Radeon settings stay behind switches; an RTX card needs none of them turned.

Grown in the open

Rust, GPL-3.0-or-later, descendant of VIctory. The commits taken from other forks keep their authors' names. Every switch is documented where it is read.

The RTX port

What an RTX card needs

Wave32 lowering that leaves partial groups alone, barriers that wait for every thread, a view heap clamp and its countermeasures (VICTORY_DYNAMIC_SLOTS), dispatches that run past 65,535 groups. The whole table is in docs/rtx.md.

Taken from the ranked forks

Dynamic slots on the capped heap, the title patches (render scale, own upscaler, watchdog off), the pipeline skip list, VICTORY_BVH_MISS, the constant-slot marks, sixteen-bit halves, the launchers; from the 8 GB fork, the constant view sizes and the clamps' waits. What stayed out, and why: the eval.

Honest numbers

Every frame-time figure of the base README is a Radeon RX 7900 XTX's. The RTX measurements are still open — the port's notes keep an unknowns list instead of made-up ones.

Getting started

  1. Install Rust and clone the repository.
  2. Build the runtime with diagnostics: 
    cargo build --profile diag -p victory --features diagnostics
  3. Start the launcher and point it at the game you own: 
    xenith.cmd
    or the graphical one: 
    xenith-ui.cmd
  4. Or launch a way directly: 
    scripts\play-nvidia.ps1 -Exe "D:\Games\GTA VI\game_scarlett_master.exe"
    with -Resolution, -Adapter, -Quality and -RayTracing on top.

Both launchers keep their choices in xenith.ini next to themselves; it is a special copy of Xenith VI's launcher, changed for this fork. The runtime keeps none of it.

The switches, for an RTX card

SwitchDoes
VICTORY_DYNAMIC_SLOTSdescriptor slots for tables made afresh; answers the card's capped view heap so tables are not refused and draws dropped
VICTORY_RENDER_SCALErenders at a part of the output's size (0.2–1.0); the title's own upscaler stretches it back
VICTORY_SKIP_PIPELINESnever makes the pipelines of the named 16-digit shader hashes (scripts/rt_off_hashes.txt pre-fills it)
VICTORY_BVH_MISS=1ray walks end at the root and miss: a ray pass cannot hang with the structure builder off
VICTORY_INDIRECT_WIDE=0dispatches cut at 65,535 groups again (unset, the card is taken to run them wide)
VICTORY_GROUP_SYNCbarrier waits: 2 every group (safe), 1 only the ones every lane runs, 0 none
VICTORY_CLAMP_WAITS=0leaves the indirect clamps' two global waits out
VICTORY_PIPELINE_WAIT_ONCE=0a pipeline past its wait budget waits again every frame, as before
VICTORY_MEMORY_CARD_MBthe most of title memory on the card (4,096)
VICTORY_D3D12_ADAPTERwhich card makes the device (name part or index)
VICTORY_UPSCALER=dlssthe title runs its FSR path and a DLSS proxy DLL beside the game speaks DLSS to the driver (the proxy is yours to supply)
VICTORY_SAVES_DIRwhere the title's saves live, instead of the data folder
shader preloadvictory translate and victory warm before a run (or the launcher's preload tick): no first-seen-places hitches

…and more, each documented in a comment where it is read; docs/rtx.md keeps the RTX table.
